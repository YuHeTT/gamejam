# 道具拾取动画（一次性 1.2s + 纵向弹跳）

## Context

目前 `PlayerItemController.TryPickUp()` 是**瞬时**的：按 J 的同一帧就调用 `Item.EnterCarriedState()`，立刻触发 `OnPickUp()`（例如「幕」立刻进入漂浮、「蓦」立刻获得冲刺），玩家完全没有"获得道具"的表演反馈。

需求是把它改造成**有前摇的拾取**：按 J 后进入一段可调时长（默认 1.2s）的拾取动画，期间道具尚未生效、不能使用道具、可以左右移动但不能跳跃；动画结束后才正式获得道具（触发 `OnPickUp`）。同时给玩家和道具做一段《以撒的结合》式的"举起 + 纵向弹跳"表现。

已确认的决策（来自用户澄清）：
- **换道具时，旧道具在动画开始的那一刻就立即掉回世界**（`ExitCarriedState`），不做回滚。
- **动画播完后道具图像恢复隐藏**（沿用现有"持有即不显示世界图像"的行为）。
- **不改 Animator**：玩家动画只由代码做挤压/拉伸（`Player_AC.controller` 与 `.anim` 一律不动）。
- **保留原始需求**：动画进行中按 J，附近有道具 → 换成它并从头重播；附近无道具 → 丢弃待拾取的道具并立刻取消动画。

## 关键技术前提（已核实）

- 玩家视觉是根物体下的子物体 `Animator`（SampleScene 中 GameObject `317415028`，其 Transform 即 `player.anim.transform`）：`Animator` + `SpriteRenderer`(sortingOrder 10) + `PlayerAnimationTriggers`。玩家根物体另有 `BoxCollider2D`（size≈0.82×1.92）与 `Rigidbody2D`。
  → **必须缩放视觉子物体，绝不能缩放根物体**，否则会改变碰撞箱。
- `playerIdle/Move/Jump/Fall/Dash.anim` 的 `m_ScaleCurves / m_PositionCurves / m_FloatCurves` **全部为空**（纯 sprite 帧切换）。
  → 代码直接写视觉子物体的 `localScale` 不会被 Animator 覆盖，安全。
- 跳跃的唯一入口是 `Player.CheckJumpInput()` 写 `jumpBufferTimer`，再由 `PlayerGroundedState.Update()` 消费。`isFloating / isStuck` 就是通过在这里提前 `return` 来禁跳的 → 新增 `isPickingUp` 沿用同一模式。
- `Item.SetWorldPresence(bool)` 关闭 `rb.simulated / col.enabled / sr.enabled`；道具持有期间图像是隐藏的。
- 交互键：J 拾取/交换/丢弃（`PlayerItemController.pickUpKey`）。

## 行为定义（改造后）

设 `pending` = 正在播放拾取动画、尚未生效的道具。

| 场景 | 行为 |
| --- | --- |
| 空闲 + 附近无道具 | 无事发生（当前行为不变） |
| 空闲 + 手上无道具 + 附近有 X | `X.BeginPickUpPreview()`，播放 1.2s 动画 |
| 空闲 + 手上有 A + 附近有 B | **A 立刻 `ExitCarriedState` 掉回世界**，然后 `B.BeginPickUpPreview()`，播放动画 |
| 空闲 + 手上有 A + 附近无道具 | 丢弃 A（当前行为不变） |
| 动画中 + 附近有 Y | Y 换出旧的 pending（旧的 `ReturnToWorld`），`Y.BeginPickUpPreview()`，**计时归零重播** |
| 动画中 + 附近无道具 | 旧的 pending `ReturnToWorld`，**立刻取消动画**，回到空闲 |
| 动画倒计时归零 | pending → `CompletePickUp()`（隐藏图像 + 触发 `OnPickUp`）→ 成为 `CurrentItem`，广播 `OnItemChanged` |

动画期间：
- `CurrentItem` 恒为 `null`（旧道具已掉、新道具尚未生效）→ 天然不会触发使用键与 `OnCarriedUpdate`；另外在 Update 里显式跳过使用键分支。
- `player.isPickingUp = true` → `CheckJumpInput` 提前 return，**禁跳**。
- 玩家仍处于 Idle/Move 常规状态 → **可左右移动**（`HorizontalMoveController` 照常）。
- 视觉：pending 的道具被放到玩家视觉子物体**正上方 `holdHeight`** 处并逐帧跟随；玩家视觉与道具一起做纵向弹跳。

## 实现步骤

### 1. `Assets/Scripts/Item/Item.cs` — 新增"预览/生效/放回"三态

在 `#region 世界/持有状态切换` 旁新增一个 region（子类仍然只应重写 `OnPickUp/OnDrop`）：

```csharp
/// <summary>拾取动画开始：立即标记为"已持有"（避免被拾取检测重复命中），但暂不触发 OnPickUp；
/// 关闭物理与碰撞、保留图像显示，供举在头顶。</summary>
public void BeginPickUpPreview(Player player)
{
    IsCarried = true;
    Holder    = player;
    if (rb  != null) rb.simulated = false;
    if (col != null) col.enabled  = false;
    if (sr  != null) sr.enabled   = true;
}

/// <summary>拾取动画结束：正式生效，触发 OnPickUp（图像转回"持有中"的隐藏状态）</summary>
public void CompletePickUp(Player player)
{
    SetWorldPresence(false);
    OnPickUp(player);
}

/// <summary>拾取动画被丢弃/替换：直接放回世界，不触发 OnPickUp / OnDrop</summary>
public void ReturnToWorld(Vector2 worldPos)
{
    IsCarried = false;
    Holder    = null;
    // ↓ 与 ExitCarriedState 原有的恢复逻辑完全一致
    ...
}
```

同时把 `ExitCarriedState` 改成复用，避免逻辑重复：

```csharp
public void ExitCarriedState(Player player, Vector2 worldPos)
{
    ReturnToWorld(worldPos);
    OnDrop(player, worldPos);
}
```

> 注意：`ReturnToWorld` 必须走 `rb.position = worldPos` 再 `transform.position = worldPos`（沿用现有注释里的原因：物理查询要用到位姿）。

### 2. `Assets/Scripts/Player/Player.cs` — 新增禁跳标记

- 在 `isStuck` 后新增：`[HideInInspector] public bool isPickingUp;`
- `CheckJumpInput()` 的条件改为：

```csharp
if (isFloating || isStuck || isPickingUp)
{
    jumpBufferTimer = 0;
    return;
}
```

> 新字段不在场景 YAML 里也没关系，Unity 会取 C# 默认值 `false`。

### 3. `Assets/Scripts/Player/PlayerItemController.cs` — 拾取动画主体

**新增 Inspector 字段**（全部可在现有场景里的 Player 物体上直接微调）：

```csharp
[Header("拾取动画")]
public float pickUpAnimDuration = 1.2f;   // 总时长；需 ≥ 三段之和，多出部分为"保持段"
public float stretchTime = 0.2f;          // 纵向拉长 / 横向缩窄
public float squashTime  = 0.3f;          // 纵向缩窄 / 横向拉长
public float returnTime  = 0.2f;          // 弹回原样
public float stretchScaleX = 0.8f;        // 拉伸态：横向
public float stretchScaleY = 1.25f;       // 拉伸态：纵向
public float squashScaleX  = 1.25f;       // 压扁态：横向
public float squashScaleY  = 0.8f;        // 压扁态：纵向
public float holdHeight = 1.2f;           // 举在头顶的高度
public int   previewSortingOrder = 11;    // 动画期间道具的渲染顺序（压过玩家视觉的 10）
```

**新增运行时状态**：`Item pendingItem`、`float pickUpAnimTimer`、`Vector3 playerVisualBaseScale`、`Vector3 itemBaseScale`、`int itemBaseSortingOrder`、`bool baseCached`。

**方法**：

- `TryPickUp()` 改造为按"是否正在播动画"分流（见上表）；空闲分支里，若手上已有道具则先 `DropCurrentItem()` 再 `BeginPendingPickUp(target)`。
- `BeginPendingPickUp(Item target)`
  1. `RestoreVisuals()`（把玩家视觉与旧 pending 的缩放、排序还原）
  2. 旧 pending 且不是 target → `old.ReturnToWorld(old.GetDropPosition(player.transform.position))`
  3. `pendingItem = target`；`target.BeginPickUpPreview(player)`
  4. 缓存 `playerVisualBaseScale`（只缓存一次）、`itemBaseScale`、`itemBaseSortingOrder`，并把道具排序改为 `previewSortingOrder`
  5. `pickUpAnimTimer = EffectiveDuration`；`player.isPickingUp = true`；`player.jumpBufferTimer = 0f`
- `CancelPendingPickUp()`：还原视觉 → `pendingItem.ReturnToWorld(...)` → 置空 → `player.isPickingUp = false`
- `CompletePendingPickUp()`：还原视觉 → `item.CompletePickUp(player)` → `CurrentItem = item` → `OnItemChanged?.Invoke(item)` → `player.isPickingUp = false`
- `UpdatePickUpAnimation()`（每帧，pending 非空时调用）：
  - 计时 `pickUpAnimTimer -= Time.deltaTime`；`elapsed = EffectiveDuration - pickUpAnimTimer`
  - 按 `stretchTime / squashTime / returnTime` 三段做 `Mathf.Lerp` 求 `(sx, sy)`，超过第三段即 `(1,1)`
  - 写 `player.anim.transform.localScale = Vector3.Scale(playerVisualBaseScale, new Vector3(sx, sy, 1))`；写 `pendingItem.transform.localScale` 同理
  - `pendingItem.transform.position = player.anim.transform.position + Vector3.up * holdHeight`
  - `pickUpAnimTimer <= 0` → `CompletePendingPickUp()`
- `RestoreVisuals()`：把玩家视觉与道具的 `localScale`、道具 `sortingOrder` 还原成缓存值。
- `EffectiveDuration = stretchTime + squashTime + returnTime + Mathf.Max(0, pickUpAnimDuration - (三段之和))`，保证形变一定走完，不会卡在半形变状态。
- `Update()` 调整：
  - `IsTeleporting` 时若在播动画 → `CancelPendingPickUp()` 再 return（避免传送把它卡在预览态）。
  - 有 pending 时：**只用 J 走"交换/丢弃"分支**，跳过使用键与 `OnCarriedUpdate`。
  - pending 被外部销毁（`pendingItem == null`）时兜底重置 `player.isPickingUp = false` 并还原视觉。
- `OnDisable()`：兜底 `CancelPendingPickUp()`，并把 `player.isPickingUp` 复位。

> 不改动 `FindNearestItem()`：pending 道具的 `IsCarried` 已为 `true`，天然被排除，不会自己命中自己。
> 不改动 `PlayerItemController` 的 `pickUpCooldown`：它同时兜住了"连按两下 J 误取消"的情况。

## 不改动的部分

- `Player_AC.controller` 与所有 `.anim`（用户明确要求不动 Animator）。
- `Entity.cs`、各 `PlayerXxxState.cs`（不新增状态，靠 `isPickingUp` 标记禁跳）。
- 所有 `Item` 子类（`MuItem / MoItem / DuskItem / SummonItem / GraveItem`）：它们只重写 `OnPickUp/OnDrop`，语义不变，只是触发时机被推迟到动画结束。

## 验证方式（在 Unity 里跑）

用 `Assets/Scenes/SampleScene.unity` 进入 Play：

1. **基础链路**：走到「幕」旁边按 J → 道具跳到头顶、玩家与道具一起拉长→压扁→回弹（约 1.2s）→ 结束后玩家才开始漂浮（`OnPickUp` 生效）、道具图像消失。
2. **禁跳可移动**：动画期间按住 A/D 能左右移动；连按 K 不跳；动画结束后 K 恢复正常起跳。
3. **不能用道具**：动画期间按 I/L 无反应（此时 `CurrentItem` 为 null）。
4. **交换（重播）**：手上已有「蓦」，走到「幕」旁按 J → 「蓦」立刻掉地上；动画期间再走到另一个道具旁按 J → 动画从头重播、换成新道具。
5. **丢弃（取消）**：动画期间走到空旷处按 J → 动画立刻停止、道具掉回原地、玩家空手。
6. **同时测试**控制台无报错、无 `NullReferenceException`（尤其传送 W 与拾取动画交叉时）。
