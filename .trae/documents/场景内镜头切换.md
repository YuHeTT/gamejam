# 场景内镜头切换（CameraZoneSwitch）

## Context（背景）

`SampleScene` 里的 **Main Camera** 是固定相机（正交 size 9、没有任何跟随脚本），一屏只能显示一个视野。

部分关卡比一屏大：玩家走到画面边缘后，需要**瞬间换镜头**到下一屏，并把玩家也瞬移到下一屏里的指定位置，同时**不改变玩家的任何状态**（速度、朝向、动画状态都保持），否则玩家会在屏幕外或被"重置"。玩家走回该边缘时，镜头要能切回原处。

目标：做一个可复用的"矩形判定区"组件，在**场景内部**实现这种瞬间换镜头效果（不是新的 Scene 加载）。

### 现状确认（已核实）
- Main Camera：`orthographic: 1`、`orthographic size: 9`、仅含 Transform/Camera/AudioListener，无自定义脚本。
- 玩家是 Rigidbody2D（Dynamic, interpolation 开）驱动的状态机；`player.rb` 为 public，可直接读写。
- 项目已有"触发器 + 玩家刚体"的先例：`windarea` 用 `OnTriggerEnter2D/Stay2D/Exit2D` 检测玩家并生效 → 说明触发方式在本项目对玩家可用，无需改碰撞矩阵。
- 已有"传送但不动状态机"的范式：`PlayerTombstoneTeleport`（对齐脚底 + `Physics2D.SyncTransforms()`）。

## 设计

### 新增一个脚本：`Assets/Scripts/two/CameraZoneSwitch.cs`

挂在带 **BoxCollider2D（勾 Is Trigger）** 的"判定区"空物体上（`[RequireComponent(typeof(Collider2D))]`，非 Trigger 时 `Debug.LogWarning` 提示，与 `windarea` 一致）。

Inspector 字段：

| 字段 | 说明 |
|---|---|
| `SwitchAxis axis` | 判定区所在镜头边缘：`Horizontal`=右侧 / `Vertical`=上侧，决定用哪个轴判断进出方向 |
| `Transform cameraIn` | **切过去**时相机要到的位置（空物体） |
| `Transform playerIn` | **切过去**时玩家要到的位置（空物体，按玩家 Transform 位置对齐） |
| `Transform cameraOut` | **回切**时相机位置；留空 = 用相机初始位置（`Start` 时缓存） |
| `Transform playerOut` | **回切**时玩家位置；留空 = 用进场前玩家的位置（切换瞬间缓存） |
| `Camera targetCamera` | 留空 = `Camera.main` |
| `float minSpeedForDirection` | 速度绝对值小于它时，改用"玩家相对判定区中心的位置"判断方向 |

核心行为：

1. **触发（单区双向 + 防抖）**
   - `OnTriggerEnter2D`：从碰撞体解析出 `Player`（`GetComponentInParent<Player>()`，非玩家直接忽略）；仅当 `_armed` 为真时执行切换，执行后 `_armed = false`。
   - `OnTriggerExit2D`：玩家离开 → `_armed = true`。
   - 这样落地后不会因为还停在区内而反复触发。

2. **方向判定**
   - 取玩家沿 `axis` 的速度分量：
     - 正 → **切过去**（用 `cameraIn` / `playerIn`）
     - 负 → **回切**（用 `cameraOut` / `playerOut`）
   - `|速度| < minSpeedForDirection` 时，用"玩家相对判定区中心在该轴上的位置"判断正负。

3. **执行（同一帧内完成，无过渡）**
   - 相机：`targetCamera.transform.position = new Vector3(anchor.x, anchor.y, 相机原 Z)`（保留 Z，避免裁剪面出问题）。
   - 玩家：`player.rb.position = target; player.transform.position = target; Physics2D.SyncTransforms();`
     - **不动** `rb.velocity`、**不调用** `Flip`、**不改** 状态机 → 速度 / 朝向 / 动画状态全部保持不变（满足需求）。
   - `Start` 里缓存相机初始位置与（首次切换时的）玩家位置，供 `cameraOut` / `playerOut` 留空时使用。

### 不改动的文件
- **Player.cs / 状态机**：不需要改。直接移动刚体即可保持状态（与"墓碑传送"不同，这里不需要 Kinematic 协程）。
- **Main Camera**：不需要挂脚本（固定相机，无跟随）。
- 项目里已有的 `ParallaxBackGround` 会随 `Main Camera` 的 x 位移自动偏移，切镜头时背景会自然跟着走，无需改动。

## 场景配置（需要你在 Unity 里做）

以"右侧"为例：
1. 在画面右侧边界放一个空物体 → 加 `BoxCollider2D` 勾 **Is Trigger**，尺寸定为判定区大小 → 加 `CameraZoneSwitch`，`axis = Horizontal`。
2. 建 4 个空物体当锚点：
   - `cameraIn`：下一屏的相机位置（= 原相机 x + 一屏宽）。
   - `playerIn`：下一屏里玩家的落点，**必须落在下一屏视野内**（例如下一屏左侧靠内一点）。
   - `cameraOut`：可留空（自动用原相机位置）。
   - `playerOut`：原屏里玩家的落点（例如原屏右侧靠内一点）。
3. 判定区所在层要能与 Player 层触发（用 Default 层即可，参考 `windarea`）。

> 关键：**落点要放在判定区外面**，否则瞬移后会立刻再次触发（虽然防抖到 `OnTriggerExit` 才复位，但仍建议落点在区外）。

## 验证方式（在 Unity 里跑）

1. 按上面摆好判定区与锚点，`axis = Horizontal`。
2. Play，玩家**向右**走进判定区 → 画面瞬间切到 `cameraIn`；玩家出现在 `playerIn`，并且**保持向右的速度与朝向继续移动**（不会变 Idle、不会翻转、不会被打断）。
3. 玩家在下一屏里**向左**走回判定区 → 画面瞬间切回原处，玩家出现在 `playerOut`。
4. 反复来回走 → 每次都是"进区才切换"，站在区内不会连续抖动。
5. 若切换瞬间画面出现 1 帧的拖影/错位（因刚体插值），我再补一个"瞬移当帧关闭插值"的小处理。

（`axis = Vertical` 时同样测"向上进区切走、向下回切"。）
